# The shared look: `packages/ui`

Decided with the user on 2026-09-17 after a survey of all twelve screens (screenshots at
1280x800). Findings: every control was a browser default with no primary/secondary hierarchy;
five board screens put the question or primary action below the fold while half the width sat
empty; each subproject centred itself at its own width; status and errors had no consistent
place or style; the home page was a bulleted list. Root cause: no shared UI layer at all.

The user chose: **board left, actions panel right** for every board screen, and one pass over
**every** screen, not just the worst ones.

## Direction

Lichess as the cue: dark by default (light honoured via `prefers-color-scheme`), calm, board
centred, system sans-serif, one accent, no decoration, nothing that moves. Scaffolding, not
gamification (endgames interview). Everything the user needs to act on is visible without
scrolling at 1280x800 and at 1280x650; the page never scrolls on a board screen.

## Package

`packages/ui` (`@human-chess/ui`): the shared look — design tokens, native-control base styles,
a handful of primitives, and the two page layouts every subproject renders inside. Depends on
react only. It is the only place app-wide CSS lives besides chessground's own stylesheet.
Subprojects keep at most a small CSS file for what is genuinely theirs (an eval scale, a move
table) and never redefine spacing, colours, buttons or layout.

### Tokens (`tokens.css`, imported by the package entry as a side effect)

CSS custom properties on `:root`, dark values by default, light values under
`@media (prefers-color-scheme: light)`:

- colour: `--hc-bg`, `--hc-surface` (panels), `--hc-surface-2` (inputs, hover), `--hc-border`,
  `--hc-text`, `--hc-text-muted`, `--hc-accent` (lichess-like blue), `--hc-on-accent`,
  `--hc-success`, `--hc-warning`, `--hc-danger`, `--hc-focus`.
- space: `--hc-space-1` 4px, `-2` 8px, `-3` 12px, `-4` 16px, `-5` 24px, `-6` 32px.
- type: `--hc-font` (system-ui stack), `--hc-mono`, `--hc-text-sm` 13px, `--hc-text-base` 15px,
  `--hc-text-lg` 18px, `--hc-text-xl` 22px; line-height 1.4.
- radius: `--hc-radius` 6px. Side panel width: `--hc-aside` 24rem. Header height: `--hc-header`.

### Base styles (`base.css`)

`body` background/text/font from tokens; links in the accent; a visible focus ring
(`--hc-focus`) on every focusable element; native `button`, `select`, `input`, `textarea`
styled once so a screen looks right even before it adopts a primitive: 15px text, 8px 12px
padding, `--hc-radius`, `--hc-surface-2` background, `--hc-border` border, hover/active
states, disabled at 50% opacity. Plain `button` is the secondary look; `button.hc-primary` is
the primary look (accent background); `button.hc-quiet` is borderless. `pre`/monospace blocks
use `--hc-mono` at `--hc-text-sm` inside a `--hc-surface` panel, never raw.

### Primitives (`components.tsx`)

- `Button({ variant?: 'primary' | 'secondary' | 'quiet', size?: 'md' | 'sm', ...buttonProps })`.
- `Field({ label, hint?, htmlFor?, children })`: label above control, hint below in muted small
  text. The wrapper is a `div`, and the label is tied to a native control by `htmlFor`/`id`;
  it never wraps, so a `SegmentedControl` inside it is safe (a wrapping label would fire the
  first button on a label click).
- `SegmentedControl<T>({ options: { value: T, label }[], value, onChange, ariaLabel })`: one
  connected group, the selected segment in accent; replaces both the radio rows and the
  "12 / 20" button pairs.
- `Status({ kind: 'info' | 'busy' | 'success' | 'error', children })`: one line, small icon
  glyph per kind, colour from tokens; `busy` shows a text spinner (no animation library).
  `role="status"` for info/busy/success, `role="alert"` for error.
- `Panel({ title?, children })`: a `--hc-surface` box with `--hc-space-4` padding.
- `Toolbar({ children })`: a row of quiet buttons with `--hc-space-2` gaps.
- `MoveTable` is NOT here; `MoveLine` stays in `packages/board`.

### Layouts (`layouts.tsx`)

- `Workbench({ title, status?, primary?, aside?, footer?, board, children })`. A two-column
  grid: the board column takes the remaining width; the aside is `--hc-aside` wide. The
  `board` prop is a render function `(sizePx: number) => ReactNode`; the layout measures its
  board column with a ResizeObserver and passes the largest square that fits both its width
  and the height left under the header (`useFitSquare`, moved here from the memory trainer's
  `useAvailableHeight`/`useElementSize`; the memory trainer then deletes its copies). The
  aside is a flex column: **title and `status` at the top, then `primary` (the question and its
  buttons, or the main action), then `children` (move list, lesson text, results) which fills
  and scrolls internally, then `footer` (a `Toolbar` of secondary actions such as flip, restart,
  new game) pinned at the bottom.** `aside` (optional) renders above `children` for extra
  panels such as the openings builder's engine lines. Below 60rem the columns stack, board
  first, with the primary block directly under the board. The page never scrolls: the
  workbench is exactly the viewport height under the header.
- `Page({ title, intro?, width?: 'narrow' (28rem) | 'medium' (36rem) | 'wide' (60rem),
  actions?, children })`: one centred column; `actions` renders at the top right of the title
  row (for the openings builder's opening picker) so the primary control is never below a
  long form.
- `AppShell({ brand, right, children })` for `apps/web`'s header; the header is the only
  full-width bar.

### Home

`apps/web` renders the route list as a responsive grid of `Card`s (title, blurb) inside a
`Page` of width `wide`, no repeated "human-chess" heading.

## Rules for adopting it in a subproject

1. A screen with a board uses `Workbench`; a setup or import screen uses `Page`.
2. The question the user must answer, or the one action that moves the screen forward, is
   `primary`. Everything else is `children` or `footer`. Only one `Button` per screen is
   `primary`.
3. Errors and progress go through `Status`; never a bare red `<p>`.
4. Radios and button-pairs for a choice become `SegmentedControl`; labelled inputs become
   `Field`.
5. Delete local CSS that the package now covers; keep what is genuinely the subproject's.
6. No engine, rules or behaviour changes in a design pass. Every number and claim shown stays
   grounded exactly as before (A1, V3). If a restyle would need a behaviour change, note it
   and leave it.
7. Verify at 1280x800 and 1280x650: no page scroll on board screens, primary block visible.
8. `AppShell` already renders the page's `<main>` and the header; a subproject renders no
   `<main>` of its own, and its screen title is the `Workbench`/`Page` `title`, not an `<h1>`.
